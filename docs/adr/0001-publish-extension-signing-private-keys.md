# Publish extension signing private keys

Signing private keys for re-signed extensions are committed publicly under `keys/*.pem` so builds can reproduce a stable extension ID without secret management. When a catalog identity has no key, the workflow generates and commits its distinct key before publishing any artifact; all later versions reuse that key. Removing an extension from the catalog does not remove its key, preserving the same ID if the extension is later restored. This deliberately allows anyone to sign a CRX with the same ID, so a CRX signature is not treated as proof of publisher authenticity; installation integrity must instead come from trusted repository changes and content hashes pinned by the Nix configuration. The dedicated key path is excluded from secret scanning and documented as public, single-purpose material; distinct keys avoid ID collisions between re-signed extensions.
