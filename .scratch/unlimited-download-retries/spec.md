# 微信与 Snipaste 下载无限重试

## 用户需求

将 update-snipaste 和 update-wechat 两个任务的下载重试次数从三次改为不限制，下载未成功时继续重试。

## 当前事实

- 两个下载器默认最多尝试三次，重试前等待时间为一秒、两秒，单次网络操作超时为六十秒。
- 下载器用于官方安装包及已有 GitHub Release 资产的回读；Snipaste 也用它下载官网版本 JSON 和 SHA-1 清单。
- GitHub API 读取和 Git 索引推送另外具有三次重试限制，其用途与文件下载不同。
- 两个 GitHub Actions 工作流目前均设置四十五分钟任务超时，并串行执行，不取消正在运行的任务。

## 已确认的决策

- 下载失败后持续重试，不设置尝试次数上限；等待间隔依次为一秒、两秒、四秒、八秒，最多六十秒，此后保持六十秒间隔。
- 每次失败记录原因及下一次重试的等待时间，保留已有下载进度日志。
- 连接错误、超时、所有 HTTP 错误、传输中断及下载截断无限重试，每次重新完整下载；版本、架构或校验和不一致、文件超大小、元数据格式异常等校验失败仍终止并保留旧索引。
- 无限重试覆盖两个任务的所有文件下载，包括官方安装包、Snipaste 版本 JSON 与 SHA-1 清单、GitHub 已有资产回读；GitHub API 请求和 Git 索引推送维持原有重试策略。
- 两个工作流的任务总超时从四十五分钟延长至三百六十分钟；保留单次网络操作六十秒超时。达到 GitHub 托管 runner 的单任务上限后结束，后续由每日定时或手动执行继续。

## 平台限制依据

[GitHub Actions 官方限制](https://docs.github.com/en/actions/reference/limits#existing-system-limits)规定 GitHub 托管 runner 单个任务最多运行六小时；达到上限后终止并标记失败。本需求取消下载次数上限，不绕过平台执行时长限制，也不自动新建执行。

## 设计确认

用户已确认完整方案，授权开始实现并测试。

## 实现与验证

- 两个下载器移除 attempts 参数和三次尝试限制，采用持续递增的尝试编号及最多六十秒的退避间隔；每次失败记录原因和等待时间。
- HTTP 非完整成功响应、网络异常、空文件和截断下载均重试；内容校验异常清理临时文件后终止，人工中断正常传递。
- 两工作流的 timeout-minutes 均为 360，两个 README 已同步说明重试边界。
- 2026-11-27 两个完整测试集通过：Snipaste 四十六项、微信四十五项，共九十一项。覆盖连续十次网络或 HTTP 失败后第十一次成功、退避上限、连续截断后的恢复、空下载、部分响应、超大小不重试及人工中断。
- git diff --check 通过；两个工作流通过 actionlint 检查，针对本地旧版工具不识别已有 ubuntu-26.04 标签的已知问题，仅忽略该标签告警。
