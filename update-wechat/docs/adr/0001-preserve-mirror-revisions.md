# 保留同一官方版本的不同镜像修订

微信官方可能在版本号不变时替换安装包，消费方又需要固定下载地址及内容校验值。因此，只要官方版本或安装包内容改变，就发布新的镜像修订；已有修订及下载地址永久保留，不覆盖历史内容。两个架构分别记录自己的最新修订，允许版本号不同，避免一个架构的发布节奏阻塞另一个架构。

每个架构独立发布一个不可变 Release，tag 使用 `wechat-<完整版本>-<架构>-<完整 SHA-256 十六进制摘要>`。内容摘要使同版本换包获得不同地址，并让失败重跑能够确定性地找到和复用已有修订；接受较长的地址，避免依赖可变的修订计数器。GitHub Releases 同时承载其他功能的产物，消费方通过微信发布索引定位文件，不使用仓库级最新 Release。

按每个架构比较官方完整版本，拒绝自动降级；发现官网版本低于索引中的版本时让任务失败并保留旧索引。相同版本而内容不同仍属于新的镜像修订，不视为降级。
