# 两架构完成校验和发布后再更新索引

两个架构的官方安装包都必须完成下载、完整版本提取和内容校验，才能开始发布镜像修订；全部镜像发布成功后，工作流才将 `update-wechat/wechat.json` 的更新提交到 `main`。任一架构校验失败时保持整个发布索引不变，避免消费方读到仅完成部分校验的更新。

GitHub Release 发布和 Git 推送不能组成一个事务。发布途中或推送索引时发生失败，已经发布的镜像修订仍然保留；重跑校验并复用已成功的发布，继续完成剩余操作，不通过删除历史资产回滚。只有完成发布的索引才进入 Git 历史。

索引以 `x86_64-linux` 和 `aarch64-linux` 为顶层键，每项仅包含 `version`、`url` 和 `sha256`。校验值使用 Nix SRI 格式，下载地址指向具体的不可变 Release 文件。首次成功执行时才生成索引，此后仅在内容变化时提交。
