# Publish immutable versioned extension artifacts

Every resolved extension version is published through GitHub Immutable Releases at a permanent version-specific URL so any historical extension lock can continue to fetch exactly the content it pins. Releases use the tag `extension-<id>-v<version>` and contain the asset `<id>-<version>.crx`; enabling Immutable Releases is a repository bootstrap prerequisite, and the workflow requires every published or reused Release to report itself as immutable before updating the lock. The per-Release check uses only the Actions token's Contents permission because reading the repository-level setting requires a separate Administration-scoped token. This includes byte-for-byte mirrors of Chrome Web Store CRXs as well as re-signed CRXs built from GitHub Release ZIPs. Rebuilding an existing extension ID and version is idempotent when the hash is unchanged and fails when the hash differs; published artifacts are never replaced or removed when a catalog entry is deleted, trading third-party artifact mirroring, additional releases, and storage for reproducibility and explicit detection of upstream asset mutation.
